## Ownership

Codex owns machine inspection, reproducible audits, compatibility tests, migration records, and the personalization evidence ledger. Claude can continue shaping the prose and teaching flow of the canonical Mixing and Mastering Guide.

Ownership is about avoiding collisions, not restricting collaboration. Either assistant may propose changes to any document, but factual claims about the installed system should link back to this repository and only one assistant should edit a file at a time.

## Handoff format

Record cross-assistant handoffs with:

```text
Date:
From:
To:
Document:
Evidence or change:
Decision needed:
Status: proposed | accepted | verified | superseded
```

## Evidence labels

- **Verified:** directly observed on this computer or confirmed by Dave.
- **Observed:** present in a project, preset, or note but not yet tested.
- **Preference:** Dave's stated taste or working habit.
- **Starting point:** a practical setting to audition, never a rule.
- **Legacy:** useful historical material that may no longer match the current system.

## Editing rules

1. Link instead of copying whole sections between the repository and vault.
2. Keep exact versions, paths, dates, and plug-in formats in the machine inventory.
3. Keep creative advice outcome-oriented; name a plug-in only when it is installed and offers a meaningful reason to choose it.
4. Separate Dave's confirmed preferences from generic engineering advice.
5. Never silently replace Claude's draft or a legacy note. Reconcile changes and record the source.
6. A setting becomes "tuned to Dave" only after it is connected to his music, monitoring setup, references, or an A/B result.
7. Treat the external Ableton storage as the archive and local storage as the active workspace. Do not direct Dave to edit an archived project in place; follow the project activation workflow instead.
